# Automatic stroke-order check against MOE 筆順學習網 — 2026-10-12

Tool: `npm run moe-check` (tools/moe-check.ts), matcher: src/content/moeMatch.ts (unit-tested, every test proven by
re-introducing a bug). MOE data (CC BY-NC-ND 3.0 TW) is cached raw in `.cache/moe/` (git-ignored) as a local
reference only. Nothing from it is in this repo: our stroke files hold only our own AnimCJK / hanzi-writer-data
shapes; the check writes only a pass/fail per character and permutations of OUR stroke indices.

## Method
- For each of the 408 characters in content/strokes/report.json, fetch `searchW.jsp?ID2=1&WORD=<char>` (follows the
  redirect to `dictView.jsp?ID=<n>`), one request at a time, ≥1.5 s apart, 20 s timeout, one retry; curl, because
  Node's fetch hit repeated connect timeouts on this host. The embedded `xml[<n>]="…"` string is parsed; the page
  must name the same character (`unicode="…"`) or it counts as not found. Version 2 is fetched when the page shows
  「有另一種寫法」 with an `ST=2` link.
- Each stroke is reduced to its start and end point in a unit square, y down: ours from the median
  (x/1024, (900−y)/1024), MOE from the Track (x/2048, y/2048).
- Cost of pairing our stroke i with MOE stroke j = |start_i − start_j| + |end_i − end_j|. Optimal one-to-one
  assignment (brute force n ≤ 8, Hungarian above).
- Outcomes: `match` (identity assignment, every pair ≤ threshold); `reorder` (non-identity, every pair ≤ threshold,
  AND our own order does not also fit — otherwise it is reported as ambiguous nomatch; no character hit that);
  `reversed` (no forward fit, but assigning on min(forward, reversed) fits with some stroke only fitting reversed);
  `nomatch` (anything else, incl. different stroke counts).
- `--apply`: match → verified.json `{ by: "moe-auto", date, method }` (founder entries never touched; a later
  non-match withdraws only a moe-auto entry); reorder → a self-reorder compose recipe (base = the same char, remove
  all, insert the same char's strokes in MOE order — identity box transform), only when the served data is exactly
  what compose-strokes would look up; then compose-strokes + build-strokes and `--apply` again, which re-checks the
  rebuilt data and verifies it. Version 2 → alternates.json only when v1 is `match` and v2 is a non-identity
  permutation of all our strokes. --apply refuses to run if any control fails or any page failed to fetch.

## Threshold calibration: 0.23 (brief's starting value 0.18)
- At 0.18 the positive control fails: 4 of the 28 founder-verified characters come out nomatch (石 max cost 0.216,
  月 0.197, 日 0.190, 目 0.196). Our font and the MOE font place strokes slightly differently; these are known-good.
- Same-count look-alikes (our 土/士/未/末/人/入/午/牛 against MOE's partner) are accepted from 0.25 up (午↔牛 at
  0.244; at 0.28 also 未↔末, 人↔入). Shown: at --threshold=0.3 six of the eight look-alike controls FAIL.
- 0.23 sits between the largest founder-verified cost (0.216) and the smallest look-alike acceptance (0.244). The
  margin is thin (~0.015 each side); characters just over it go to the founder, they are not verified.
- The threshold only decides whether a stroke "exists" in both; ORDER is decided by the assignment. For every one
  of the 17 reorders, the identity pairing cost of a moved stroke was 0.17–1.04 against 0.02–0.13 for the MOE
  pairing — none was a near tie.
